评测积分收费规则 · 图文说明

这次改版后，用户花钱买到的是「评测积分」。美元只在付款那一刻出现； 账户里能看到的、每次评测扣掉的、到期作废的，全部是积分。

先记住五句话，整套规则就是它们的展开：
  1. 每付 $1 到账 250 基础积分，套餐还会额外赠送；
  2. 字 / 词 / 句评测成功扣 1 分，段落扣 2 分——失败、报错不扣；
  3. 积分充进账号共享池，名下所有 API Key 一起用，不分家；
  4. 每笔充值的积分 30 天有效，扣分时先扣最早到期的那一笔；
  5. 新账号注册就送 600 分试用（30 天有效），不用绑卡。

下文截图均来自 Global 门户（Dashboard → Billing）的演示数据，界面为英文版线上样式。

PART A · 规则怎么理解

A1 · 和旧模式的区别

以前用户账户里放的是美元余额，按当月调用量套一个阶梯单价、一次调用扣几厘钱——用户很难心算「这笔钱够用多少次」。 现在只有一种资产：积分。充值时一次性换算清楚，之后每次评测扣整数分，余额一眼能看懂。

A2 · 钱怎么变成积分

分两步：先按固定汇率换基础积分——每 $1 换 250 分（不足 $1 的零头向下取整）； 再看选的是哪个套餐，按套餐比例加赠送。倒过来算，基础价约合 $0.004 / 分， 选高档套餐后单价更低（见 A6 单价表）。

A3 · 一个完整例子：$150 充 Advanced

付 $150，选 Advanced（+10% 赠送）→ 先换 37,500 基础分 → 再送 3,750 分 → 一共到账 41,250 分，从到账日起 30 天内有效。

amount_usd = 150
base_points = floor(150 × 250) = 37,500
bonus_points = round(37,500 × 10%) = 3,750
credited_points = base + bonus = 41,250
points_expire_at = 到账日 + 30 天

A4 · 什么时候扣分

只有一条判断标准：这次评测成功了没有。成功按题型扣 1 或 2 分； 鉴权失败、引擎报错、超时等一切失败情况都不扣，用户不为故障买单。

A5 · 有效期与「先到期先扣」

每充值一次，就生成一个独立的「积分批次」，各自倒计时 30 天。 扣分时系统总是先扣最早到期的批次（同一天到期的，先扣先充的那笔）， 让用户的积分尽量少过期。批次用完标记为 exhausted；到期没用完的部分作废，不退款。

A7 · 用户在哪里看到这一切

账单页首屏就是积分余额和试用额度；充值历史里，每一笔记录以「+多少分」为主信息， 美元金额只作为支付凭证陈列在旁边。

PART B · 后端怎么实现

B1 · 支付与到账流程

1

→
2

创建 PayPal 订单

3

Capture 成功

同一事务写交易 + 批次 + 余额

→
4

积分批次生效

仅 succeeded 计入余额

幂等要求

  • 重复 capture / webhook 重放，不得重复加积分
  • pending 交易不加积分；只有 succeeded 入账
  • 支付前的 quoted_points 仅供确认；最终以 capture 返回的字段为准

B2 · 批次扣减的排序规则

扣减顺序：expires_at ASC（最早到期优先）；同日到期再按 created_at ASC。 批次状态：active（有剩余且未过期）→ exhausted（用完）/ expired（过期作废，不退款）。 余额、消耗记录、批次状态更新必须在同一个数据库事务里完成。

B3 · 接口清单（对接用）

接口 职责 关键字段
GET /api/billing/pricing 充值规则权威源 evaluation_point_rules · topup_packages
POST /api/billing/topups/order 创建 PayPal 订单 amount_cents · package_id → quoted_points
POST …/topups/:id/capture 捕获并入账 base / bonus / credited_points · points_expire_at
GET /api/billing/summary 账户总览 evaluation_points_balance · expiring_soon · next_expiry_at
GET /api/billing/evaluation-points/batches 批次明细 按 expires_at ASC；remaining / status
GET /api/billing/transactions 充值历史 credited_points 为主列；金额仅对账

B4 · 实现检查清单

必须做对

  • 用户侧只展示积分，不展示驱动业务的美元余额
  • 充值入账与批次写入在同一 DB 事务
  • 扣分跨批次 FIFO，且与余额更新同事务
  • capture / webhook 幂等
  • 套餐最低额由服务端校验

不要做

  • 不要用美元余额驱动限流 / 拒服
  • 不要只存总余额、不存批次（否则无法解释到期）
  • 不要让前端自算赠送比例 / 有效期
  • 不要对失败调用扣分
  • 不要把 pending 交易加进余额
