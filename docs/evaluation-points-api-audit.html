类型
优先级
原则：赠送比例、最低金额、预设档位、输入金额后的到账积分、有效期天数，一律以服务端为准。 前端用本地公式仅作 Demo 兜底；正式路径以 quoted_points / GET /billing/pricing 为准。

后端算价

用户改金额 → 下单接口返回 quoted_points；capture 返回 base_points / bonus_points / credited_points。

前端预留字段

类型与 bridge 已对齐契约；接口就绪后直接灌数据，无需再改页面结构。

已接线接口 vs 页面出入

接口清单

用上方筛选按类型 / 优先级过滤。红色左边线 = P0；紫色 = 新增路径。

POST /api/billing/topups/order P0 补充 后端算价

创建 PayPal 订单。服务端校验套餐最低金额并计算到账积分。

req: amount_cents, package_id
res: paypal_order_id, transaction_id, quoted_points, package_id, amount_cents
Checkout Step 3
POST /api/billing/topups/:transactionId/capture P0 补充 后端算价

同一事务：PayPal capture → 写交易 → 写积分批次 → 更新余额。幂等，禁止重复加分。

res: base_points, bonus_points, credited_points, point_balance_before/after, points_expire_at, used_points, remaining_points, package_id
PayPal onApprove
GET /api/billing/evaluation-points/batches P1 新增

唯一必须新增的 HTTP 路径。支撑到期分布图与批次明细；同日多笔不得按日期合并。

batches[].id, transaction_id, package_id, credited_points / used_points / remaining_points, expires_at, created_at, status(active|exhausted|expired)

#项通过标准
1改金额下单同一 package 下不同 amount，quoted_points 由服务端返回且前后端一致
2Capture 幂等重复 capture 不重复加分；仅 1 条 batch

4FIFO最早到期批次优先扣减
